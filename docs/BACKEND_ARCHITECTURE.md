# Sovereign Exchange Backend

This repository is the exchange backend. The future frontend is a separate repository and is a client of this system.

## Authority boundary

The matching engine is authoritative Rust state. No browser, Vercel function, JavaScript runtime, database, or HTTP request participates in the matching hot path.

```
Frontend
   |
   v
Control plane / API gateway
   |
   v
Rust exchange nodes
   |
   +-- deterministic sequencing
   +-- price/time matching
   +-- risk
   +-- ledger / settlement
   +-- durable journal
   +-- snapshots / replay
   +-- peer replication
   +-- market data
```

## Backend invariants

1. One matching owner per instrument per epoch.
2. Canonical sequencing is generated by the Rust authority.
3. Every peer message carries protocol version, sender, epoch and sequence.
4. Sequence gaps are detected before state advances.
5. Duplicate messages are rejected.
6. The peer data plane uses bounded binary frames rather than JSON.
7. QUIC is the reliable peer transport. Unreliable datagrams are reserved for explicitly lossy telemetry.
8. Production peers require certificate pinning or mTLS. Anonymous peer joins are forbidden.
9. Durable commands are journaled before acknowledgement.
10. Snapshots are tied to a journal position and deterministic state fingerprint.
11. Failover is epoch-fenced. A stale owner cannot resume writes after promotion.
12. Wall-clock time is never a matching input.

## Failure model

CI is expected to break the backend on:

- loss, duplication and reordering
- sequence gaps and stale epochs
- duplicate client orders
- queue exhaustion
- malformed and oversized frames
- journal corruption/truncation
- process restart
- peer restart/isolation
- state divergence
- stale leadership
- resource exhaustion

## Transport

The peer transport is Rust-native QUIC. Quinn supports simultaneous client/server endpoints and both ordered streams and application datagrams, making it suitable for a peer-to-peer backend where reliable command replication and lower-overhead telemetry have different semantics. citeturn0search2turn0search6

The current QUIC layer is deliberately only the transport foundation. Before real-money deployment, certificate provisioning, mutual peer authentication, persistent peer identity, retransmission/gap recovery, canonical commit semantics and WAN chaos testing must be wired into the exchange node.

## Frontend contract

A future frontend may consume authenticated APIs for:

- sessions
- order submission
- cancel/replace
- market-data snapshots
- incremental market-data events
- execution reports
- balances and positions
- health/readiness

The frontend may never create exchange sequence numbers, mutate canonical state directly, or become a matching authority.
